# EquipVision

Прототип помощника инженера для обхода промышленного оборудования: камера телефона, распознавание визуальных признаков дефектов, телеметрия, цифровая карточка. Кейс КСТ Энерго Инжиниринг, хакатон «Кибер 102». План и границы MVP — в [docs/MVP_PLAN.md](docs/MVP_PLAN.md).

Вся цепочка работает: камера, модель распознавания, телеметрия, правила диагностики, карточка и история.

## Запуск

Нужен Python 3.13. Node.js не нужен: клиент — обычные HTML и JS, их раздаёт сервер.

```bash
cd server
python -m venv .venv
.venv/Scripts/python -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
.venv/Scripts/python -m pip install -r requirements.txt
.venv/Scripts/python tools/fetch_model.py
.venv/Scripts/python run.py
```

Вторая строка ставит PyTorch под видеокарту NVIDIA; без неё поставится версия для процессора. `fetch_model.py` один раз скачивает основу модели распознавания дефектов (346 МБ) и модель речи (45 МБ) — после этого интернет серверу не нужен. Если основы нет, сервер запустится с заглушкой вместо модели и напишет об этом в журнал.

Сервер поднимется по HTTPS на порту 8443 и напечатает адреса вида `https://192.168.x.x:8443`. Откройте такой адрес на телефоне в той же сети Wi-Fi и один раз согласитесь с предупреждением о самоподписанном сертификате. Без HTTPS браузер телефона не даст доступ к камере.

Если телефон не открывает страницу: отключите на ноутбуке VPN (он может перехватывать трафик локальной сети) и проверьте брандмауэр.

Параметр `--db путь` запускает сервер на отдельной базе — удобно для пробного прогона, чтобы не трогать основную.

Чтобы показать систему пользователям вне локальной сети, есть режим демонстрации:

```bash
.venv/Scripts/python run.py --public
```

Сервер слушает обычный HTTP на порту 8080 на всех интерфейсах и рассчитан на HTTPS-туннель или обратный прокси перед ним, например `cloudflared tunnel --url http://localhost:8080`. Пользователям даётся адрес `https://…` от туннеля: камеру и микрофон браузер открывает только по HTTPS. Тестовые источники кадров в этом режиме выключены. Пароли демонстрационных учётных записей лежат в репозитории, поэтому держать сервер открытым дольше показа не стоит.

Для разработки на самом ноутбуке:

```bash
.venv/Scripts/python run.py --no-tls
```

Откроется `http://localhost:8000`. Для машины без камеры есть тестовые источники, только в этом режиме: `?src=test` — сгенерированная картинка, `?src=photo&n=2` — одно из размеченных фото-примеров с лёгким движением, `?src=label&label=PCP-3` — нарисованный шильдик (с `&qr=1` — QR-код). Параметр `?eq=P-101` пропускает идентификацию. Это средство разработчика, а не загрузка фото: рабочий путь — живая камера.

## Интерфейс

Оформление — Material Design 3, написано вручную в `client/styles.css`: без сборки и без внешних библиотек, потому что серверу и телефону недоступен интернет.

- **Цвета** — роли M3 (primary, surface-container, error-container и остальные) из схемы для исходного цвета `#0061A4`; «успех» и «предупреждение» добавлены как расширенные цвета. Светлая и тёмная темы переключаются по настройке устройства.
- **Шрифт** — Roboto, лежит в `client/fonts` (лицензия SIL OFL 1.1, файл рядом). Значки — Material Icons, встроены в страницу.
- **Навигация** — пять разделов агрегата: «Осмотр», «Датчики», «Узлы», «Паспорт», «История». На телефоне это нижняя панель, на широком экране — боковая, а камера остаётся на экране при переходе между разделами.
- **Экран осмотра** — чтобы меньше листать, блоки свёрнуты до заголовков и раскрываются нажатием: диагнозы (раскрыт только первый, самый серьёзный), «Отметить дефект вручную», «Выполненные работы», «Что система сейчас не оценивает».
- **Компоненты** — верхняя панель, карточки, списки, поля с подписью на рамке, кнопки (основная, тональная, контурная, текстовая), метки состояния, индикаторы, полноэкранный диалог для документов, всплывающие сообщения о результате действий.

## Карта обхода

На главном экране — маршрут по всем агрегатам, сгруппированный по месту установки. Кнопка «Начать обход» создаёт обход; дальше приложение показывает следующий агрегат и отмечает каждый:

- **осмотрен** — когда по нему сохранён осмотр; после сохранения приложение возвращает на карту и называет следующий агрегат;
- **пропущен** — только с указанием причины;
- **не осмотрен** — остался без отметки к моменту завершения обхода.

Итог завершённого обхода (осмотрено, пропущено с причиной, не осмотрено) остаётся на карте. Маршрут — все агрегаты базы по порядку мест установки.

## Фото и статистика дефектов

- Когда камера записывает признак, сервер сохраняет этот кадр с обведённой областью. При ручной отметке прикладывается текущий кадр камеры. Выбрать файл нельзя.
- Ошибочную находку инженер удаляет значком корзины в списке «Зафиксировано в этом осмотре». Её фото стирается, диагноз пересчитывается, и камера не записывает этот признак на этом узле снова до нового осмотра; вручную отметить его можно. Сохранённые в историю записи не удаляются.
- Фото видны в списке находок осмотра, в истории агрегата и попадают в отчёт: в PDF — раздел «Фотографии дефектов», в Excel — лист «Фото дефектов».
- Статистика дефектов считается по истории: по признаку, по узлу, по месяцам, по агрегатам. Показывается на главном экране (весь парк), во вкладке «История» агрегата и в отчёте.
- На новой базе в истории есть девять демонстрационных дефектов с пометкой «демонстрационная запись», чтобы статистика не была пустой. Это не данные заказчика.

## Режим обучения

Переключатель на вкладке «Осмотр». Приложение ведёт новичка по узлам агрегата по шагам:

- на карточке шага — что проверять, как смотреть и что считается нормой;
- поверх видео — рамка кадрирования и подсказка, что искать на этом узле;
- находки системы скрыты до конца: сначала новичок сам отмечает, что видит.

В конце выставляется оценка из 100: половина — полнота (на скольких узлах камера действительно задержалась и дан ответ), половина — внимательность (сколько признаков, записанных камерой, новичок отметил сам). По каждому узлу даётся замечание. Результаты видны мастеру и администратору на главном экране, новичку — только свои.

## Вход и роли

Без входа доступна только сама страница: все запросы к `/api` и канал кадров требуют сессии. Пароли хранятся как хеши PBKDF2 с солью; сессия живёт 12 часов в cookie с флагом HttpOnly, в базе лежит только хеш её токена. Внешних сервисов входа нет — всё локально.

| Роль | Логин | Что может |
| --- | --- | --- |
| инженер | `engineer` | смотреть карточки и телеметрию, вести осмотр, записывать находки, сохранять осмотр, выгружать отчёты |
| мастер | `master` | всё то же и регистрация ТО и замены узлов — они обнуляют счётчики ресурса |
| администратор | `admin` | всё то же и управление пользователями |

Пароли демонстрационных записей лежат в `server/data/users.seed.json`. Файл в репозитории, поэтому перед любым реальным применением пароли нужно сменить. Автор записи в истории берётся из сессии, а не из запроса.

## Отчёт

Кнопки «Отчёт PDF» и «Отчёт Excel» на экране агрегата выгружают карточку, текущую диагностику с причинами и рекомендациями, состояние и ресурс узлов, историю, а также кто и когда сформировал отчёт. Оба формата строятся из одних и тех же строк.

Для PDF нужен шрифт с кириллицей. На Windows берётся Arial, на Linux — DejaVu, Liberation или PT Astra; свой шрифт можно положить в `server/assets/fonts/`. Если шрифта нет, сервер ответит об этом, а Excel продолжит работать.

## Паспорт и документация

В карточке агрегата есть раздел «Паспорт и документация» из двух частей.

**Паспортные данные**, выписанные из документов заказчика по разделам: общие сведения, технические характеристики, материалы, электродвигатель, редуктор, защиты, комплектность, проектные условия. У каждого раздела указан документ-источник. Ресурс до списания (11 000 ч) используется в расчёте остатка.

**Сами документы** — без перепечатки, страницами сканов:

- у каждого винтового насоса свой паспорт агрегата и свои паспорта двигателя, редуктора и датчика;
- общие для четырёх насосов: инструкция по эксплуатации и обслуживанию, перечень смазочных материалов, руководства на двигатель и мотор-редуктор, чертежи со схемой и перечнем блокировок, опросные листы, сертификаты.

Всего 14 документов на агрегат, 218 страниц в комплекте. Страницы рисует сервер (pypdfium2), поэтому они открываются в браузере телефона без интернета и без программы для PDF. Сканы подшиты в разном порядке и повёрнуты по-разному — в просмотре есть кнопка «Повернуть», по нажатию на страницу она увеличивается.

## Идентификация оборудования

Приложение открывается на экране идентификации. Раз в секунду кадр уходит на `/api/identify`:

1. **QR-код** (OpenCV). Код содержит `EQV:<идентификатор>`. Срабатывает с первого кадра.
2. **Шильдик** (RapidOCR, модели PP-OCRv4 лежат внутри пакета, работает без интернета на процессоре, 0,4–0,7 с на кадр). Прочитанный текст сверяется с серийными номерами в базе. Похожие символы (O и 0, I и 1, S и 5, B и 8) считаются одинаковыми.
3. **Ручной выбор** из списка — всегда на экране.

Агрегат открывается сам, только если серийный номер совпал точно и в двух кадрах подряд. При расхождении в один символ система предлагает кандидатов и ждёт подтверждения: у соседних агрегатов номера отличаются одной цифрой (`21031004-3` и `21031004-4`).

Шильдики и QR-коды для стенда печатаются со страницы `/labels.html`.

В базе пять агрегатов:

- `P-101` — центробежный, к нему подключена телеметрия заказчика. Серийный номер, нормативы узлов и история — демонстрационные.
- `PCP-1` … `PCP-4` — винтовые AMS PCP60S12/3 с серийными номерами `21031004-1` … `21031004-4`. Все характеристики взяты из паспортов заказчика; наработка — демонстрационная, в документах её нет. Телеметрия к ним не подключена, поэтому оцениваются только осмотр и ресурс.

### Выбор голосом

Кнопка «Назвать голосом» на экране идентификации записывает три с половиной секунды и отправляет звук на сервер. Распознаёт его движок Vosk с малой русской моделью (Apache-2.0, 88 МБ на диске) — на процессоре сервера, без интернета, около 80 мс на фразу.

- Словарь распознавания ограничен: «насос», «агрегат», «номер», «позиция», «центробежный», «винтовой» и числа. Так распознавание устойчивее к шуму, чем свободная диктовка.
- Агрегат называется по числу в обозначении: «насос сто один» — `P-101`, «винтовой номер три» — `PCP-3`. Число можно сказать и по цифрам: «один ноль один».
- Агрегат открывается сам, только если во фразе есть и слово про агрегат, и число, и каждое слово распознано уверенно. Иначе система показывает, что услышала, и просит подтвердить или повторить: при маленьком словаре любой шум превращается в какое-нибудь слово.

Микрофон, как и камера, работает только по HTTPS или на localhost.

## Обмен кадрами

Клиент шлёт в `/ws/vision` один JPEG (до 640 пикселей по длинной стороне) и ждёт ответа перед следующим кадром:

```json
{"seq": 1, "width": 640, "height": 480, "ms": 5.1, "stub": true,
 "detections": [{"label": "corrosion", "title": "Коррозия", "score": 0.4, "box": [0.61, 0.43, 0.79, 0.58]}]}
```

`box` — `x1, y1, x2, y2` в долях кадра.

Текстовое сообщение `{"type": "focus", "equipment_id": "P-101", "component": "seal"}` сообщает серверу, какой узел осматривает инженер. Признак, который держится в трёх кадрах из восьми, записывается как находка этого узла. Без выбранного узла кадры анализируются, но ничего не записывается.

## Правила диагностики

Правило — запись в списке `RULES` в `server/app/rules.py`: условия, диагноз, рекомендация, узлы, которые стоит осмотреть камерой, и гипотезы, которые правило уточняет. Причины в ответе собираются из условий автоматически, с текущими значениями.

Тесты проверяют правила на всех 500 записях заказчика (сверка с его колонкой «Диагноз»), сопоставление серийных номеров, вход, права ролей и оба формата отчёта:

```bash
cd server
.venv/Scripts/python -m unittest discover -s tests
```

## Модель распознавания

Замороженная сеть DINOv2 base (Apache-2.0) превращает кадр в признаки участков 14×14 пикселей. Маленькая обученная голова оценивает каждый участок по трём признакам: коррозия, течь, следы перегрева. Соседние участки выше порога объединяются в область. На RTX 2060 кадр 640×480 обрабатывается примерно за 35 мс, на процессоре — около 0,8 с.

Данные:

- коррозия — маски набора [Corrosion in Industrial Complexes in Ostrava](https://zenodo.org/records/11235637) (CC BY 4.0), авторское разбиение 75/15/15;
- течь — 291 фото с рамками из набора [Multimodal Transformer Defect Recognition Dataset](https://zenodo.org/records/22771088) (CC BY 4.0, силовые трансформаторы) и 7 фото заказчика. Течью считаются только рамки видимого размера: около двух третей рамок набора — точки на общих планах подстанций, где течь неразличима; они не считаются ни течью, ни её отсутствием;
- следы перегрева — 5 фото заказчика с ручной разметкой;
- «здесь ничего нет» — 22 страницы документации заказчика, 160 фото того же набора трансформаторов с другими дефектами и 360 фото обычных сцен (помещения, столы, ноутбуки, люди) из COCO val2017 — только со свободной лицензией: CC BY, CC BY-SA, без известных ограничений.

Проверочные и тестовые части наборов в обучении не участвуют. По проверочной части нового набора выбран порог течи, тестовая использована один раз для итоговой цифры.

Проверка (`server/models/defect-head/meta.json`):

| Что проверено | На чём | Результат |
| --- | --- | --- |
| Течь, новое оборудование | тестовая часть набора трансформаторов: 15 фото с течью, 72 без | найдено 14 из 15; ложных срабатываний 0 из 72 |
| Течь, новое оборудование | проверочная часть того же набора: 28 с течью, 122 без | найдено 26 из 28; ложные на 5 из 122 |
| Течь, фото заказчика | каждую сцену предсказывает голова, не видевшая её | найдено на 6 фото из 7; ложные на 3 из 32 |
| Следы перегрева, фото заказчика | то же | найдено на 4 фото из 5; ложных 0 из 34 |
| Следы перегрева, ложные срабатывания | 237 фото трансформаторов, где наших следов перегрева нет | 0 |
| Коррозия | 15 фото тестовой части Остравы | полнота 94%, точность 80%, IoU 0,76 по участкам |
| Ложные срабатывания, любой признак | 28 отложенных страниц документации | 0 |
| Ложные срабатывания, любой признак | 81 отложенное фото обычных сцен: комнаты, столы, ноутбуки, люди | 0 |
| Съёмка с экрана, имитация | фото заказчика, 6 случайных «съёмок» каждого | течь 41 из 42, перегрев 26 из 30; ложных срабатываний нет (192 съёмки без течи, 204 без перегрева) |

Камера телефона видит не только оборудование, поэтому в обучении есть обычные сцены как примеры «дефектов нет» — с затемнением, цветной подсветкой и смазом. На отложенных фото таких сцен ложных срабатываний нет.

Что сделано для качества:

- **Отрицательные примеры из документации**: ложные срабатывания на отложенных документах упали с 8 страниц из 28 до нуля.
- **Порог течи 0,5.** При пороге 0,3 новая модель находила все 7 течей заказчика, но давала ложную течь на 14 фото из 32: рамки в новом наборе широкие, и модель начинала принимать за течь ржавые и замасленные поверхности.
- **Учёт осматриваемого узла**: признак, не характерный для узла (течь на клеммной коробке, перегрев на уплотнении), показывается серым пунктиром и сам в находки не записывается; вручную отметить его можно. Список — `SIGN_PLACES` в `server/app/inspection.py`.
- **Калибровка уверенности** — процент на экране подогнан по предсказаниям для сцен, которых модель не видела.

Как собрать данные и переобучить:

```bash
cd server
.venv/Scripts/python tools/build_no_defect.py        # страницы документации, нужен pdftoppm
.venv/Scripts/python tools/fetch_transformer.py      # около 690 фото из архива Zenodo, 15–20 минут
.venv/Scripts/python tools/fetch_scenes.py           # около 440 фото обычных сцен, 65 МБ
.venv/Scripts/python tools/train_defects.py --docs --transformer --scenes --thresholds 0.5,0.5,0.3 --save
.venv/Scripts/python tools/eval_capture.py
```

Чтобы добавить свои фото течи или перегрева: `tools/grid_sheets.py` рисует на них сетку координат, рамки вписываются в `training/annotations.json`.

Первый запуск обучения занимает около 8 минут (признаки сети кэшируются в `tmp/feat-cache`), повторные — около 5. Не запускайте обучение одновременно с сервером или другим обучением на той же видеокарте: на машине с 16 ГБ памяти второй процесс падает.
